### Nils's claude · May 20, 11:43 HKT, 2026

**Review-driven fixes to PR #152.** Critical: corrected the factually wrong TLS-backend claim across this crate's docs (`src/readme.md`, `src/sprint.md`) and propagation chain — the iOS cross-compile actually pulls **`ring 0.17`** via reqwest's `rustls-tls` default (`Cargo.lock` has zero `aws-lc-rs`); the build worked because `ring 0.17.x` now has first-class iOS support, not because `aws-lc-rs` was the default. Important: removed stale "NOT yet validated" comments in `src/readme.md` Verification block and `build-xcframework.sh`'s header (the same PR validates the script, so its self-description had to follow). Fixed a real bug in `build-xcframework.sh` — the Swift glue (`auki_network_swift.swift`) was being packaged into the xcframework's `Headers/` dir by `xcodebuild -create-xcframework -headers $BINDINGS`; now moved to a sibling `$OUT/swift/` dir so xcframework Headers contain only the FFI `.h` + `module.modulemap` and the `.swift` is consumed at the SwiftPM-package level. Added doc-comments on `ClusterEntry` / `CreateClusterOutcome` explaining derived `Eq` is byte-equality (use `name`/`manager_peer_id` for semantic comparison; multiaddrs can differ in whitespace/encoding/order). Documented in `src/readme.md` "What does NOT work yet" that the Rust `with_http` escape hatch (custom reqwest::Client for proxies/TLS roots/timeouts) is intentionally not exposed at Stage 1, with a new parking-lot entry tracking the FFI-shape question. Re-validated: `cargo test -p auki-network-swift` 4/4 green; `build-xcframework.sh` now produces a clean two-slice xcframework whose Headers contain only `*FFI.h` + `module.modulemap`, with the Swift glue in `target-xcframework/swift/`.

### Nils's claude · May 19, 13:46 HKT, 2026

**New crate: UniFFI Swift bindings for `auki-network` (Stage 1 — Discovery surface).** Mirrors `auki-network-py`'s root Discovery surface and per-component binding convention (no umbrella `auki-swift`): `DiscoveryClient` UniFFI object with async `list_clusters`/`create_cluster`/`liveness_check`/`rotate_manager`/`deregister` plus sync `new`/`base_url`, `ClusterEntry`/`CreateClusterOutcome` records, and a flattened `DiscoveryError` (reqwest/libp2p types hidden; PeerId/Multiaddr cross as canonical strings). UniFFI proc-macro mode (`setup_scaffolding!`), futures driven by tokio via `#[uniffi::export(async_runtime = "tokio")]`. Depends on `auki-network` with only the `discovery_client` feature, so Stage 1 stays off the libp2p iOS-link sharp edges. Host `cargo build`/`cargo test -p auki-network-swift` green (error-mapping + conversion + seam-parse unit tests, no network). iOS XCFramework build is scripted (`build-xcframework.sh`) but not yet validated. Stage 2 (audio streams) and Stage 3 (`auki-domain-swift` cluster/peer enumeration) are scoped in `src/sprint.md`; the async-vs-`-py`-sync API-shape divergence is flagged in `parking_lot.md` for human confirmation. Implements the iosapp Q1 decision (UniFFI, thin, prost payloads via swift-protobuf later).
