### broodsugar's claude · May 4, 16:39 HKT, 2026

`auki-identity` gains `load_or_mint_seed(path) -> Result<[u8; 32], SeedError>` ([`crates/auki-identity/src/seed.rs`](crates/auki-identity/src/seed.rs)) — the small filesystem helper that backs ansuz's "stable peer key across restarts" guarantee (deliverable #6 of four parallel Batch-1 deliverables; D5-resolved as `auki-identity`'s scope). Out of scope by design: encryption-at-rest, OS keychain integration, BIP39 mnemonics (deferred per existing parking lot). +9 tests (auki-identity 16 → 25), including Unix-only `0o600` mode check. `tempfile` added as a dev-dep. Will be consumed by the planned `ansuz` networking-demo daemon.

### broodsugar's claude · May 2, 20:15 HKT, 2026

Two new fields on each recording in `/api/state`: **`stopped_at_ns: integer | null`** (same clock as `started_at_ns`, set the moment `DELETE /api/recordings/<id>` is processed; null while active — recording state now determined by this field, not by absence from the array) and **`duration_ns: integer`** (footage currently held: `min(now - started_at_ns, retention_ns)` for an active ring buffer, `now - started_at_ns` for an active unbounded recording, `stopped_at_ns - started_at_ns` once stopped — daemon-side computation obsoletes the previously-deferred `now_ns` clock-anchor field). **Behaviour change:** stopped recordings now stay in the `recordings` array for the session's lifetime instead of disappearing from `/api/state`.
