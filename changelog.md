`auki-logs`: `Log<T>::set_retention(retention_ns)` added in [`crates/auki-logs/src/lib.rs`](crates/auki-logs/src/lib.rs) — closes the long-flagged gap that left Sentinel's `PATCH /api/buffer` endpoint returning `501 Not Implemented` (per the [Control API spec](docs/control-api.md), an operator can extend a buffer's retention while it's recording to capture a transient event). Updates in-memory state and rewrites `manifest.json` atomically (`.tmp` → fsync → rename) so the change survives daemon restart. Disk-write-first ordering: the manifest is persisted before the in-memory field is updated, so a failed write leaves the log unchanged. Eviction is not retroactive — it runs as part of `append`, not `set_retention`, so a quiescent log retains its current segments until something appends after the change. Negative values rejected (`Error::Manifest`); zero is permitted and disables future eviction. **Design clarification.** The application owns the policy (when, why, what value, who's authorized); the SDK exposes the mechanism because the underlying `retention_ns` state IS owned by `Log<T>`. Close-and-reopen as an alternative was rejected — unacceptable data-loss windows for the actual `PATCH /api/buffer` use case. 4 new tests covering shrink-during-run, persistence across reopen, negative-rejection, and zero-disables-future-eviction; auki-logs test count 10 → 14. See [`crates/auki-logs/changelog.md`](crates/auki-logs/changelog.md) for detail.
