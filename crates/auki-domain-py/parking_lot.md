# Parking Lot — `auki-domain-py`

Open questions specific to this crate. Cross-cutting questions live in the root [`parking_lot.md`](../../parking_lot.md).

---

- **2026-05-13 — #1 Wire `stream_provider` Python callable through `init_domain`.** Phase 1 of `auki-domain-py` (this crate's initial PR) accepts no `stream_provider` kwarg — the wrapper unconditionally passes `auki_network::stream_runtime::decline_all_streams()` as the runtime's stream provider. That means producer daemons (BoosterApp, Sentinel) can `init_domain` and join the cluster, but every inbound `/auki/stream/0.1.0` subscription is typed-declined before any frames flow.

  **Why deferred.** Wiring a Python callable through requires either (a) re-using `auki-network-py`'s `build_stream_provider` (currently `pub(crate)` — would need to be promoted to `pub`) AND depending on `auki-network-py`'s Rust lib from here, or (b) duplicating ~500 lines of `PyStreamDecision` / `PyAcceptInfo` / `PyDeclineReason` / `PyJpegFrame` / `PyPointCloudFrame` / `PyJointEncodersFrame` / `PyProducerFrame` pyclass plumbing in this crate. (a) is blocked by a Rust lib-name collision: `auki-network`'s `[lib] name` resolves to `auki_network` (default from package name) and `auki-network-py`'s `[lib] name = "auki_network"` explicitly. Both are direct deps of `auki-domain-py` (`auki-network` for `Swarm` / `build_swarm` / `DiscoveryClient` / `decline_all_streams`; `auki-network-py` would be added for the stream-provider bridge). Cargo refuses to link two libs with the same name. (b) is too much duplication for one PR — the stream-type pyclass surface is the largest single feature of `auki-network-py`.

  **Resolution options:**
  - **(A) Shared private crate `auki-py-bridge`** containing `build_stream_provider` + all the stream-type pyclasses. Both `auki-network-py` and `auki-domain-py` depend on it. Clean separation; some refactor cost; new crate to maintain.
  - **(B) Rename `auki-network-py`'s `[lib] name` to `auki_network_py`** so it doesn't collide with `auki-network`'s lib name. Keep `[tool.maturin] module-name = "auki_network"` so the Python module import path stays unchanged. Verify maturin's wheel-rename pipeline does the cdylib→Python-module renaming cleanly. Low-cost; depends on maturin's renaming actually working.
  - **(C) Lift `StreamProvider` bridging logic into `auki-network`** behind an opt-in feature flag. Adds PyO3 as an optional dep of the Rust SDK crate, which violates the "WASM-friendly" design goal but is the cleanest dep graph.
  - **(D) Stop honoring the per-component PyO3 wrapper convention** and merge `auki-domain-py` into `auki-network-py`. Pragmatic but loses the lifecycle-isolation the per-component pattern provides.

  **Recommendation:** (B) — try the rename first. If maturin's wheel-rename works, this is a 30-minute task and unblocks every future cross-py-crate dep. If it doesn't, fall back to (A). **Stakeholders:** Nils.

- **2026-05-13 — #2 Wire `runtime.open_*_stream()` consumer-side methods through `DomainHandle`.** Same blocker as #1 (lib-name collision blocks reusing `auki-network-py`'s `PyStreamSubscription` / `PyConsumerFrame` / `PyOpenStreamError` pyclass surface). Park is Rust-side and not affected; only impacts Python consumers if any appear. Defer until a real ask materializes — `auki-domain-py` v1 deliberately under-specifies the consumer surface because no Python consumer exists today. Same resolution paths as #1.

- **2026-05-13 — #3 Wire `handle.update_cluster_doc(new_doc)` for SSE-driven membership refresh.** `init_domain` only performs the initial create-and-register; the daemon should subscribe to Discovery's SSE stream (via `DiscoveryClient::subscribe`) and feed fresh `ClusterDoc`s in so the libp2p allow-list stays in sync as peers join / leave the cluster. The `ClusterDoc` Python pyclass lives in `auki-network-py` — same lib-name-collision blocker as #1 and #2. In the meantime, the local allow-list reflects cluster membership at `init_domain`-time; peers joining the cluster after the daemon boots won't be dialable until the daemon restarts. The SDK-side tightening filed in [`auki-network/parking_lot.md`](../auki-network/parking_lot.md) — "ClusterRuntime owns its SSE subscription internally" — would resolve this entirely by making the daemon not have to drive the subscription at all. If that lands first, #3 collapses.

- **2026-05-13 — #4 `DomainAlreadyExists.existing` should carry the winner's `ClusterDoc`.** Today, the exception carries only `.identity` / `.cluster_name` strings; the `existing: ClusterDoc` payload from the SDK is dropped. Surfacing it as a Python `ClusterDoc` pyclass requires reachability from this crate — same lib-name-collision blocker. Greenland T12's `try-join → create-if-none → fall-back-to-join` retry can still work by re-issuing `init_domain` with the same name (which will go through the non-create register path on the second call), but a direct `existing.peer_count` / `existing.current_manager_peer_id` accessor would be operator-friendlier for logging. Resolution via the same paths as #1.
