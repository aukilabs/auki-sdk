- **2026-05-13 — #1 RESOLVED → Propagate: Wire `stream_provider` Python callable through `init_domain`.** Path (B) executed: `auki-network-py`'s `[lib] name` renamed `auki_network` → `auki_network_py`; `build_stream_provider` promoted `pub(crate)` → `pub`; `stream_types` module made `pub mod`; `auki-domain-py` deps on `auki-network-py` and threads the Python `stream_provider` kwarg through `build_stream_provider`. Maturin's `[tool.maturin] module-name = "auki_network"` keeps the Python import path unchanged. **Propagate:** README's "What's NOT in this PR" section in [`README.md`](README.md) needs the `stream_provider` row removed; the analogous block in [`src/lib.rs`](src/lib.rs)'s crate-level doc comment needs trimming too.

- **2026-05-13 — #2 Wire `runtime.open_*_stream()` consumer-side methods through `DomainHandle`.** ~~Same blocker as #1 (lib-name collision)~~ Unblocked by #1's resolution — the lib-name fix means `auki-network-py`'s `PyStreamSubscription` / `PyStreamEntry` / `PyOpenStreamError` are now reachable from this crate. Still deferred because no Python consumer exists today (Park is Rust-side). Implementation cost is moderate (~150 lines wrapping `RustClusterRuntime::open_stream`'s three variants); pick up when a real ask materializes.

- **2026-05-13 — #3 Wire `handle.update_cluster_doc(new_doc)` for SSE-driven membership refresh.** ~~Same blocker as #1 and #2~~ Unblocked by #1's resolution. `init_domain` still only performs the initial create-and-register; the daemon needs to subscribe to Discovery's SSE stream (via `DiscoveryClient::subscribe`) and feed fresh `ClusterDoc`s into `handle.runtime.update_cluster_doc(new_doc)` so the libp2p allow-list stays in sync. In the meantime, the local allow-list reflects cluster membership at `init_domain`-time; peers joining the cluster after the daemon boots won't be dialable until the daemon restarts. BoosterApp's K1 demo is a small static cluster — restart-on-membership-change is acceptable for now. The SDK-side tightening filed in [`auki-network/parking_lot.md`](../auki-network/parking_lot.md) — "ClusterRuntime owns its SSE subscription internally" — would collapse this entry entirely.

- **2026-05-13 — #4 RESOLVED → Propagate: `DomainAlreadyExists.existing` collapsed by switching to `init_or_join_domain`.** Phase 2 switched the underlying call to `auki_domain::init_or_join_domain` (added in the same cut), which collapses the create-vs-join discrimination at the Rust layer. The Python `init_domain` entry point no longer raises `DomainAlreadyExists` in the happy path — race-loss becomes a normal-happy-path join. The exception class stays in the module for forward-compat (if a daemon ever opts into the create-only path via a future `auki_domain.init_domain_strict` matching Rust `init_domain`, it would raise this). **Propagate:** crate-level doc comment in [`src/lib.rs`](src/lib.rs) still mentions `DomainAlreadyExists` as a routine outcome — should reframe as "only raised if a daemon explicitly opts into the create-only path." Likely deprecate / hide the exception class once Phase 3 lands the typed create-only entry point.

- **2026-05-13 — #5 Phase 3: typed create-only `init_domain_strict` Python entry point.** With Phase 2 collapsing race-loss into the happy path, daemons that *want* to know whether they're the initial Manager (e.g. Greenland T2+T3+T4's Manager-role state, once that lands SDK-side) no longer have a Python surface to opt in. Add `auki_domain.init_domain_strict(...)` (or `init_domain(create_only=True)`) wrapping the Rust `init_domain` (NOT `init_or_join_domain`). Returns `DomainHandle` on `Created`, raises `DomainAlreadyExists` with the winner's `ClusterDoc` (also #4 follow-up) on race-loss. Defer until Manager-role state is real on the Rust side; today no daemon cares.
