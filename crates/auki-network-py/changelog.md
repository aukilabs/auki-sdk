### broodsugar's claude · May 6, 14:00 HKT, 2026

`auki_network.discovery` Python submodule landed — [Vinland](https://www.notion.so/3585c8e9659280699681caec256e0616) Batch 2, the PyO3 wrapper around `auki_network::discovery_client` from [v0.0.18](https://github.com/aukilabs/auki-sdk/releases/tag/v0.0.18). Sync-shaped per Pattern A — the SDK owns the asyncio loop on its tokio worker; sidecar consumers stay sync-shaped, matching grimsby's `auki-network-py` precedent. Pins v0.0.18 by adding `"discovery_client"` to the `auki-network-rs` features list. Reassigned from Arshak to SDK Claude on 2026-05-06 ("i am taking arshaks work, lets go").

**Public surface** (new `auki_network.discovery` submodule):

```python
from auki_network.discovery import (
    DiscoveryClient,
    DiscoveryUnreachable,
    DiscoveryRejected,
    DiscoveryClockError,
)

client = DiscoveryClient("http://10.0.0.5:8080")

# `seed` is the PARENT wallet seed (32 bytes). The wrapper internally
# derives the peer-key wallet via `derive_child("peer/v1")` and signs
# with that. Distinct from `cluster.spawn(seed=peer_seed)` which takes
# the *peer* seed already derived. Mirrors the Rust shape.
doc = client.register(
    seed=wallet_seed,
    cluster_name="vinland",
    addresses=["/ip4/192.168.9.130/tcp/4001"],
    expected_app_id="sentinel",  # optional
    note=None,                    # optional
)
# doc is a cluster.ClusterDoc — same Python type cluster.load_doc returns.

doc = client.fetch("vinland")
client.deregister(seed=wallet_seed, cluster_name="vinland")
```

**Pattern A bridge**: each method `block_on`s on the existing process-wide `cluster_tokio_runtime()` (the one `cluster.spawn` already lazy-inits), so two SDK pieces share one tokio runtime in a Python process. `py.allow_threads()` releases the GIL during the I/O so other Python threads stay live. Cheap to construct (`reqwest::Client` pools connections internally); shareable across Python threads — one `DiscoveryClient` per Discovery URL.

**Three typed Python exceptions** for the Rust `DiscoveryError` variants:

- `DiscoveryUnreachable` — transport / DNS / connect / TLS / timeout. Discovery isn't reachable; the daemon retries or surfaces as a startup failure (Vinland D3 — the SDK does not fall back to a local `cluster.json`).
- `DiscoveryRejected` — HTTP non-2xx. Carries `.status: int` and `.body: str` attributes so `try / except DiscoveryRejected as e: if e.status == 404: ...` works cleanly. Daemons treating clean shutdown as idempotent catch this on the second `deregister` call against an already-removed entry.
- `DiscoveryClockError` — `SystemTime::now()` failed (pre-1970 or post-2262). Rare; means the host clock is broken — the SDK can't sign without a valid timestamp.

**Identity decision: ****`seed: bytes`**** (32 bytes, parent), not a ****`Wallet`**** object.** PyO3 doesn't gracefully share pyclasses across crates without making them `pub`, and the existing `cluster.spawn(seed=...)` precedent is already the seed-bytes shape. Operators do `seed = auki_identity.load_or_mint_seed(seed_path)` once; for `cluster.spawn` they then derive the peer seed via `auki_identity.Wallet.from_seed(seed).derive_child("peer/v1").seed()`; for `discovery.register` they pass the parent seed directly and the wrapper does the same `derive_child` internally. Documented prominently in the module docstring with a side-by-side table — the asymmetry mirrors the underlying Rust APIs.

**No new production deps on this crate** beyond extending the existing path-dep — `auki-network-rs`'s `discovery_client` feature pulls in `reqwest` / `base64` / `auki-jcs` / `thiserror` transitively. The wrapper itself adds a path-dep on `auki-identity` (the Rust crate, not `auki-identity-py`) for `Wallet::from_seed` reconstruction inside the FFI seam — sub-microsecond per call, no I/O.

**Tests**: 7 new Rust-side smoke tests + 17 new Python-side tests (10 offline + 7 against a live Discovery binary, gated on `DISCOVERY_BIN` env var — same gate the Rust-side `tests/discovery_integration.rs` uses).

Rust-side (`discovery::tests`, 6) + the surface-pin in `tests::module_exposes_discovery_submodule_with_documented_surface` (1) — auki-network-py Rust test count 26 → 33. The 6 module tests cover: constructor + URL trim, register seed-length validation, register multiaddr validation, deregister seed-length validation, fetch against unreachable URL → typed `DiscoveryUnreachable`, module-level surface pin (DiscoveryClient + 3 exception types).

Python-side (`python_tests/test_discovery.py`):
- **Offline (10)**: submodule surface pin, top-level `from auki_network import discovery`, constructor URL-trim, repr, register-rejects-short-seed, register-rejects-long-seed, register-rejects-invalid-multiaddr, deregister-rejects-short-seed, register-accepts-empty-addresses (the wrapper doesn't reject empty `addresses` — the operator might want to register without reachability info temporarily), fetch-against-unreachable-URL raises typed `DiscoveryUnreachable`.
- **Live Discovery (7, gated on `DISCOVERY_BIN`)**: register returns full ClusterDoc (single-peer boot), three peers converge in `vinland` (Sentinel/Booster/Park sequential register + fetch shows all three), deregister removes the entry from a subsequent fetch, deregister-already-removed raises `DiscoveryRejected` with `.status == 404`, fetch unknown cluster raises `DiscoveryRejected` with `.status == 404`, path-traversal `cluster_name` (`"../etc/passwd"`) is rejected, returned ClusterDoc isinstance-checks against `cluster.ClusterDoc` (schema-parity smoke test — same Python type `cluster.load_doc` returns and `cluster.spawn` accepts).

The fixture spawns Discovery as a subprocess on a fresh tempdir + ephemeral loopback port (binds `127.0.0.1:0`, reads the port, drops the listener; Discovery binds the same port a moment later), polls `GET /clusters` until 200 OK, yields the base URL, and tears the subprocess down on `finally` (terminate → wait timeout=2 → kill if still alive). Same shape as the Rust-side integration test.

Test counts: Rust-side `cargo test -p auki-network-py` 33 (was 26; +7); Python-side `pytest python_tests/` 39 + 7 skipped without `DISCOVERY_BIN` / 46 with `DISCOVERY_BIN` set (was 22 / 22). No breaking changes.

### broodsugar's claude · May 5, 13:00 HKT, 2026

Docstring clarification on `cluster.spawn`: the `seed` kwarg is the **peer** seed (post-wallet-derivation), not the wallet seed. Surfaced 2026-05-05 by BoosterApp Claude when wiring deliverable #7 — the underlying `auki_network::cluster_runtime::ClusterRuntime::spawn` calls `PeerIdentity::from_seed(seed)` (direct ed25519), not `from_wallet`, so passing the wallet seed produces a swarm whose PeerId differs from `wallet.derive_child("peer/v1").peer_id()` (the canonical wallet-rooted peer identity that operators put in `cluster.json`); libp2p Noise then rejects every dial. The function signature was vague ("seed: 32 bytes") and didn't flag the trap. New docstring spells out the wallet-rooted invocation pattern inline (`peer_seed = wallet.derive_child("peer/v1").seed()` → `cluster.spawn(seed=peer_seed, ...)`); the README's spawn snippet now demonstrates the same pattern explicitly using `auki_identity.Wallet.from_seed(...).derive_child("peer/v1").seed()`. Companion change in this PR: `Wallet.seed() -> bytes` added to `auki-identity-py` so Python consumers can extract the derived seed bytes (the upstream Rust `auki_identity::Wallet::seed` was always there; the binding never wired it). Sibling docstring update in `auki_network::cluster_runtime::ClusterRuntime::spawn` / `::from_swarm` carries the same clarification on the Rust side. No behavior change; 12 Rust + 18 Python tests still green. Will land in v0.0.15.

### broodsugar's claude · May 5, 12:00 HKT, 2026

Crate created — PyO3 bindings for `auki-network`'s cluster layer. Lets a Python process participate in an ansuz cluster as a libp2p peer; the unblock for [BoosterApp](https://github.com/aukilabs/boosterapp)'s sidecar `/api/cluster` and deliverable #7 (sidecar libp2p integration). Naming is per-component (`auki-network-py`), matching the existing `auki-identity-py` pattern over an umbrella `auki-py` — decided through-Nils between SDK Claude and BoosterApp Claude on 2026-05-05; the surface contract was hashed out in the same exchange (eight contract questions, all resolved before any code landed). The exposed Python surface is a single sub-module: `auki_network.cluster.{ParticipantInfo, PeerSnapshot, ClusterDoc, ClusterRuntime, load_doc, spawn}`. `ParticipantInfo` is typed `#[pyclass]` with a kwargs-only `#[new]` constructor (every wire-shape field, `peer_id` parsed wrapper-side via `PeerId::from_str` → `ValueError` on bad input), getters for all 9 fields, `__repr__`, `__eq__` (no `__hash__` since `session_now_ns` mutates per provider call); the constructor is what consumers use to return values from their `participant_provider` callable. `PeerSnapshot` is the typed read-only view the runtime emits — `peer_id: str`, `info: ParticipantInfo`, `first_seen_ns: int` — Python doesn't construct these directly. `ClusterDoc` is opaque (only `peer_count` and `cluster_name` exposed for sanity-checks; the wrapper validates everything at parse time so a `ClusterDoc` instance is by construction valid). `cluster.load_doc(path)` wraps `auki_network::cluster_doc::load` with full `LoadError` mapping: `Io` → `OSError`, all parse / version / peer_id / multiaddr errors → `ValueError` with the offending value in the message. `cluster.spawn(seed, doc, participant_provider, *, listen_addresses=None, agent_version=None, enable_mdns=True)` boots an `auki_network::cluster_runtime::ClusterRuntime` against a process-wide tokio multi-thread runtime owned in `OnceLock<Runtime>` (lazy-initialized on first call; one runtime services all `ClusterRuntime`s in the process). The wrapper validates `seed` length wrapper-side (`ValueError` if `len != 32`, no Rust panic path); listen addresses default to OS-chosen TCP+QUIC on `0.0.0.0` (`/ip4/0.0.0.0/tcp/0`, `/ip4/0.0.0.0/udp/0/quic-v1`); `agent_version` defaults to `auki-network-py/<crate-version>`. The `participant_provider` Python callable is wrapped as an `Arc<dyn Fn() -> Option<RustParticipantInfo> + Send + Sync>` that re-acquires the GIL on each invocation (one per inbound `/auki/cluster/1.0.0` request), calls the closure, and returns `Some(info)` / `None` to the runtime: `None` for Python `None`, `None` (with `tracing::warn!`) for any exception, `None` (also warn-logged) for a non-`ParticipantInfo` return — never panics, never lies. `ClusterRuntime` is a `#[pyclass]` wrapping `Mutex<Option<RustClusterRuntime>>`; `peers()` returns `list[PeerSnapshot]` from any thread (lock-light, mirrors the Rust API), `shutdown()` consumes the inner via `Option::take()`. Use-after-shutdown is a noisy `RuntimeError` rather than a silent no-op. Manual `Debug` impl on the wrapper (the inner Rust `ClusterRuntime` doesn't derive `Debug`, so `Result::expect_err` couldn't format it). Default `tracing-subscriber` lazy-init writes to stderr with `RUST_LOG`-driven filtering (default `warn`); systemd captures stderr into journald, same pattern as `auki-identity-py`. Build mode is the standard PyO3 dual-mode: `cargo test` runs the Python interpreter via the `auto-initialize` dev-feature (12 Rust-side smoke tests including a real-runtime spawn → peers → shutdown round trip on a loopback listener), and `maturin develop` enables `pyo3/extension-module` for a Python-importable wheel. Cross-language test pin: a `print_python_e2e_peer_ids` Rust test emits the canonical PeerIds for the test seeds (`[0x10; 32]` and `[0x11; 32]`) so the Python E2E test bakes the strings without depending on `auki-identity-py` for derivation. 18 Python tests passing under `pytest python_tests/`: module surface pin, `ParticipantInfo` round-trip + `__eq__` + `__repr__` + invalid-peer-id rejection + `cluster_joined_at_ns=None`, `load_doc` happy + 4 error variants, `cluster.spawn` argument validation (seed length, multiaddr), spawn → shutdown lifecycle, two-runtime discovery (cross-language analog of `auki_network::cluster_runtime::tests::two_runtimes_discover_each_other_via_cluster_doc` — fixed-port loopback peers converging within 10s, both seeing each other's `app` / `name` / `peer_id`), and a raising-provider smoke test. New regular deps: `multiaddr` 0.18 (parsing the `listen_addresses` kwarg), `tokio` with `rt-multi-thread` (the runtime singleton), `tracing` + `tracing-subscriber` (default subscriber + `warn!` on caught provider exceptions), `libp2p-identity` 0.2 (PeerId parse/format on the FFI seam — the underlying `ParticipantInfo.peer_id` is `libp2p_identity::PeerId`, Python sees a string). Workspace `Cargo.toml` updated to include the new crate. PyPI publishing punted — distribution is `pip install git+...#subdirectory=` for now; will revisit alongside `auki-identity-py`'s PyPI question. **Will land in v0.0.14** — v0.0.13 cut at 2026-05-05 03:00 HKT bundling ansuz Batch 2 (#33, #34), the `Option<ParticipantInfo>` follow-up (#35), and the `auki-logs::Log<T>::set_retention` addition (#36); this crate's PR went up ~4 minutes after, so it slots into the next tag.
