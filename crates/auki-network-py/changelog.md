### broodsugar's claude · May 5, 13:00 HKT, 2026

Docstring clarification on `cluster.spawn`: the `seed` kwarg is the **peer** seed (post-wallet-derivation), not the wallet seed. Surfaced 2026-05-05 by BoosterApp Claude when wiring deliverable #7 — the underlying `auki_network::cluster_runtime::ClusterRuntime::spawn` calls `PeerIdentity::from_seed(seed)` (direct ed25519), not `from_wallet`, so passing the wallet seed produces a swarm whose PeerId differs from `wallet.derive_child("peer/v1").peer_id()` (the canonical wallet-rooted peer identity that operators put in `cluster.json`); libp2p Noise then rejects every dial. The function signature was vague ("seed: 32 bytes") and didn't flag the trap. New docstring spells out the wallet-rooted invocation pattern inline (`peer_seed = wallet.derive_child("peer/v1").seed()` → `cluster.spawn(seed=peer_seed, ...)`); the README's spawn snippet now demonstrates the same pattern explicitly using `auki_identity.Wallet.from_seed(...).derive_child("peer/v1").seed()`. Companion change in this PR: `Wallet.seed() -> bytes` added to `auki-identity-py` so Python consumers can extract the derived seed bytes (the upstream Rust `auki_identity::Wallet::seed` was always there; the binding never wired it). Sibling docstring update in `auki_network::cluster_runtime::ClusterRuntime::spawn` / `::from_swarm` carries the same clarification on the Rust side. No behavior change; 12 Rust + 18 Python tests still green. Will land in v0.0.15.

### broodsugar's claude · May 5, 12:00 HKT, 2026

Crate created — PyO3 bindings for `auki-network`'s cluster layer. Lets a Python process participate in an ansuz cluster as a libp2p peer; the unblock for [BoosterApp](https://github.com/aukilabs/boosterapp)'s sidecar `/api/cluster` and deliverable #7 (sidecar libp2p integration). Naming is per-component (`auki-network-py`), matching the existing `auki-identity-py` pattern over an umbrella `auki-py` — decided through-Nils between SDK Claude and BoosterApp Claude on 2026-05-05; the surface contract was hashed out in the same exchange (eight contract questions, all resolved before any code landed). The exposed Python surface is a single sub-module: `auki_network.cluster.{ParticipantInfo, PeerSnapshot, ClusterDoc, ClusterRuntime, load_doc, spawn}`. `ParticipantInfo` is typed `#[pyclass]` with a kwargs-only `#[new]` constructor (every wire-shape field, `peer_id` parsed wrapper-side via `PeerId::from_str` → `ValueError` on bad input), getters for all 9 fields, `__repr__`, `__eq__` (no `__hash__` since `session_now_ns` mutates per provider call); the constructor is what consumers use to return values from their `participant_provider` callable. `PeerSnapshot` is the typed read-only view the runtime emits — `peer_id: str`, `info: ParticipantInfo`, `first_seen_ns: int` — Python doesn't construct these directly. `ClusterDoc` is opaque (only `peer_count` and `cluster_name` exposed for sanity-checks; the wrapper validates everything at parse time so a `ClusterDoc` instance is by construction valid). `cluster.load_doc(path)` wraps `auki_network::cluster_doc::load` with full `LoadError` mapping: `Io` → `OSError`, all parse / version / peer_id / multiaddr errors → `ValueError` with the offending value in the message. `cluster.spawn(seed, doc, participant_provider, *, listen_addresses=None, agent_version=None, enable_mdns=True)` boots an `auki_network::cluster_runtime::ClusterRuntime` against a process-wide tokio multi-thread runtime owned in `OnceLock<Runtime>` (lazy-initialized on first call; one runtime services all `ClusterRuntime`s in the process). The wrapper validates `seed` length wrapper-side (`ValueError` if `len != 32`, no Rust panic path); listen addresses default to OS-chosen TCP+QUIC on `0.0.0.0` (`/ip4/0.0.0.0/tcp/0`, `/ip4/0.0.0.0/udp/0/quic-v1`); `agent_version` defaults to `auki-network-py/<crate-version>`. The `participant_provider` Python callable is wrapped as an `Arc<dyn Fn() -> Option<RustParticipantInfo> + Send + Sync>` that re-acquires the GIL on each invocation (one per inbound `/auki/cluster/1.0.0` request), calls the closure, and returns `Some(info)` / `None` to the runtime: `None` for Python `None`, `None` (with `tracing::warn!`) for any exception, `None` (also warn-logged) for a non-`ParticipantInfo` return — never panics, never lies. `ClusterRuntime` is a `#[pyclass]` wrapping `Mutex<Option<RustClusterRuntime>>`; `peers()` returns `list[PeerSnapshot]` from any thread (lock-light, mirrors the Rust API), `shutdown()` consumes the inner via `Option::take()`. Use-after-shutdown is a noisy `RuntimeError` rather than a silent no-op. Manual `Debug` impl on the wrapper (the inner Rust `ClusterRuntime` doesn't derive `Debug`, so `Result::expect_err` couldn't format it). Default `tracing-subscriber` lazy-init writes to stderr with `RUST_LOG`-driven filtering (default `warn`); systemd captures stderr into journald, same pattern as `auki-identity-py`. Build mode is the standard PyO3 dual-mode: `cargo test` runs the Python interpreter via the `auto-initialize` dev-feature (12 Rust-side smoke tests including a real-runtime spawn → peers → shutdown round trip on a loopback listener), and `maturin develop` enables `pyo3/extension-module` for a Python-importable wheel. Cross-language test pin: a `print_python_e2e_peer_ids` Rust test emits the canonical PeerIds for the test seeds (`[0x10; 32]` and `[0x11; 32]`) so the Python E2E test bakes the strings without depending on `auki-identity-py` for derivation. 18 Python tests passing under `pytest python_tests/`: module surface pin, `ParticipantInfo` round-trip + `__eq__` + `__repr__` + invalid-peer-id rejection + `cluster_joined_at_ns=None`, `load_doc` happy + 4 error variants, `cluster.spawn` argument validation (seed length, multiaddr), spawn → shutdown lifecycle, two-runtime discovery (cross-language analog of `auki_network::cluster_runtime::tests::two_runtimes_discover_each_other_via_cluster_doc` — fixed-port loopback peers converging within 10s, both seeing each other's `app` / `name` / `peer_id`), and a raising-provider smoke test. New regular deps: `multiaddr` 0.18 (parsing the `listen_addresses` kwarg), `tokio` with `rt-multi-thread` (the runtime singleton), `tracing` + `tracing-subscriber` (default subscriber + `warn!` on caught provider exceptions), `libp2p-identity` 0.2 (PeerId parse/format on the FFI seam — the underlying `ParticipantInfo.peer_id` is `libp2p_identity::PeerId`, Python sees a string). Workspace `Cargo.toml` updated to include the new crate. PyPI publishing punted — distribution is `pip install git+...#subdirectory=` for now; will revisit alongside `auki-identity-py`'s PyPI question. **Will land in v0.0.14** — v0.0.13 cut at 2026-05-05 03:00 HKT bundling ansuz Batch 2 (#33, #34), the `Option<ParticipantInfo>` follow-up (#35), and the `auki-logs::Log<T>::set_retention` addition (#36); this crate's PR went up ~4 minutes after, so it slots into the next tag. BoosterApp deliverable #7 (sidecar libp2p integration) pins against v0.0.14 once cut.
