### broodsugar's claude · May 5, 10:30 HKT, 2026

`ClusterRuntime` `participant_provider` signature changed from `Arc<dyn Fn() -> ParticipantInfo + Send + Sync>` to `Arc<dyn Fn() -> Option<ParticipantInfo> + Send + Sync>` — small follow-up promised to Booster claude after #34 landed. Returning `None` tells the runtime to drop the inbound request's reply channel without sending a response; the requester sees a request timeout, which is the correct signal when the consumer can't fill in valid info (session clock not yet bound during sidecar startup, Python `participant_provider` raised an exception that the PyO3 wrapper caught and logged, or any other transient inability to construct a valid `ParticipantInfo`). The runtime is unaffected — it stays alive, continues processing other events, and accepts future requests from the same peer. Inside the request handler in `run_task`, the existing `let info = (participant_provider)(); send_response(channel, info)` becomes `if let Some(info) = (participant_provider)() { send_response(channel, info) }` plus a comment distinguishing the None-from-the-provider case (drop) from the peer-not-in-doc case (also drop, but for a different reason — the cluster doc is the trust boundary, not the responder's transient state). Existing fixture closures wrap their static `ParticipantInfo` in `Some(...)`. **Breaking API change** for any out-of-tree consumer holding a `ParticipantInfoProvider` directly — but the only consumer today is internal tests; `auki-network-py` (in flight on the BoosterApp side) hasn't shipped yet, so the breaking change has zero external impact. New test `cluster_runtime::tests::provider_returning_none_drops_the_reply` (the eighth `cluster_runtime` test) sets up two runtimes: rt_a's provider always returns `None`, rt_b's is a normal fixture; asserts the asymmetric peer view (rt_a sees rt_b because rt_b replies normally, rt_b does NOT see rt_a because rt_a drops the channel), then verifies both runtimes still respond to `peers()` and `shutdown()` calls without panic or hang. 55 unit + 3 integration + 2 doctest with `--features swarm` (was 54 + 3 + 2); 64 unit with `--all-features` (was 63); no-features and `--features app_instance` paths unchanged. Module-level docstring on `ParticipantInfoProvider` documents the `None` semantics inline. Outer README's "Cluster runtime (M1)" table row for `participant_provider` updated; `src/README`'s mod-block sketch updated; tests table gains the new row. No new parking-lot items. ### broodsugar's claude · May 5, 09:30 HKT, 2026

`ClusterRuntime` landed — ansuz networking-demo deliverable #4, the higher-level cluster orchestration on top of the `cluster_protocol` primitive (#3). New `auki_network::cluster_runtime` module (gated on `swarm`) wraps a libp2p `Swarm<Behaviour>` + tokio task in an opaque shape: `ClusterRuntime::spawn(seed, doc, swarm_config, participant_provider)` builds the swarm and starts the driver; `ClusterRuntime::from_swarm(swarm, doc, participant_provider)` accepts a pre-built swarm (the test-and-tooling seam — lets a caller learn the swarm's bound addresses before constructing the cluster doc); `peers() -> Vec<PeerSnapshot>` returns the live view; `shutdown(self)` is the explicit clean exit; `Drop` is the safety net. Both lifecycle paths abort the driver task and close the swarm. Driver behaviour: auto-dials every peer in `cluster.json` that has at least one address; on `ConnectionEstablished` to a known peer, sends a `ClusterRequest`; on inbound request from a known peer, invokes `participant_provider` and replies; on inbound request from an unknown peer, drops the channel (their request times out — the cluster doc IS the trust boundary, period); on response from a known peer, stores in the state map keyed by `PeerId`; on `ConnectionClosed`, marks the entry disconnected (preserving `first_seen_ns` for same-session reconnect) and schedules a redial; on `OutgoingConnectionError`, schedules a redial. Reconnect is per-peer exponential backoff, `INITIAL_BACKOFF = 1s` doubling up to `MAX_BACKOFF = 60s`, reset on a successful connect. The driver's `tokio::select!` loop arms a `RECONNECT_TICK = 500ms` interval to walk the schedule and fire due dials. **`first_seen_ns` semantics**: the peer's `session_now_ns` value at the moment of the **first** response received from their current session — sticky across reconnects within the same peer-session, reset if the peer's `session_id` changes (peer restarted with a fresh session). The store-response logic compares incoming `session_id` against the existing entry's; same-session refresh keeps `first_seen_ns`, different-session replace resets it. **`cluster_joined_at_ns` setter is the consumer's job** — the runtime explicitly does not mutate the local `ParticipantInfo`; the consumer reads `peers()` and sets the field on its own outbound info accordingly. The runtime's `participant_provider` callable is invoked **per inbound request** (not once at spawn time) so `session_now_ns` is fresh on each reply rather than stale at runtime-spawn — this is what lets `auki-py`'s Python `participant_provider` plug in cleanly. **Shape decision** (recorded in the ansuz Notion doc 2026-05-05): opaque runtime owning its own swarm + task, *not* a real `NetworkBehaviour`. The wrapper consumers are Boosterapp via `auki-py` (Python can't drive a libp2p loop, wants opaque) and Sentinel (Rust, but uses `cluster_protocol::Behaviour` directly and drives its own loop); neither wants `NetworkBehaviour` composition, and the runtime path is meaningfully simpler to write and test. A future Rust consumer that wants `NetworkBehaviour` composition can build it on top of `cluster_protocol` directly. New regular deps gated on `swarm`: `tokio` (`macros` + `rt` + `sync` + `time`) for the driver task primitives; `futures` (default-features off) for `StreamExt::next` on the swarm. Both were already dev-deps for the existing swarm tests; promoting to regular deps adds nothing to the dep graph that `libp2p` 0.56's `tokio` feature didn't already pull in. 7 new tests, all `#[tokio::test(flavor = "multi_thread")]`: `two_runtimes_discover_each_other_via_cluster_doc` (the basic happy path — both sides see the other in `peers()` within 10s), `three_runtimes_form_full_mesh` (each runtime sees the other two — within 15s), `peer_leaving_drops_off_other_peers` (3 runtimes converge, kill one, surviving 2 drop the departed peer from `peers()` while keeping each other), `unknown_peer_is_not_surfaced` (a swarm not in the doc dials in and sends a request — the runtime drops it silently, `peers().len() == 0`), `shutdown_is_idempotent_and_drops_state` and `drop_without_explicit_shutdown_cleans_up` (lifecycle paths return promptly, no deadlock), `spawn_outside_tokio_runtime_returns_error` (calling `from_swarm` from a `std::thread` → `SpawnError::NoTokioRuntime`). Test counts: 54 unit + 3 integration + 2 doctest with `--features swarm` (was 47 + 3 + 2); 63 unit with `--all-features` (was 56); no-features and `--features app_instance` paths unchanged. **Closes ansuz Batch 2.** No new parking-lot items raised. Boosterapp's `auki-py` PyO3 wrapper (`cluster.spawn` etc.) is unblocked.

### broodsugar's claude · May 4, 16:30 HKT, 2026

`app_instance::derive()` landed — implementation of ansuz #5, the per-machine identifier that distinguishes two daemons of the same `app` running on different hardware. New `auki_network::app_instance` module behind a default-off `app_instance` feature (non-WASM by design — depends on the `mac_address` crate, which uses platform syscalls `getifaddrs` / `GetAdaptersAddresses`). Recipe locked per ansuz D4: enumerate interfaces, skip loopback (all-zero MAC) and locally-administered MACs (U/L bit `0x02` on the first octet), sort the remaining MACs lexicographically by raw bytes, render the smallest as 12 lowercase hex chars without separators (`aabbccddeeff`). Sorting (rather than relying on OS interface enumeration order) gives a stable selection across platforms and reboots for a fixed hardware set. `DeriveError` enum: `NoNetworkInterfaces` (empty enumeration), `NoSuitableMac` (everything filtered — typical in containers), `Io(std::io::Error)` (syscall failure). Public API: `derive() -> Result<String, DeriveError>` for production; `derive_from(macs: &[[u8; 6]]) -> Result<String, DeriveError>` as the testing seam (pure, no side effects). 9 new tests covering the locked `[0x00,0x16,0x3e,0xab,0xcd,0xef]` → `"00163eabcdef"` cross-language vector, schema (12 lowercase hex), `NoNetworkInterfaces` on empty, `NoSuitableMac` on loopback-only / locally-administered-only, IEEE selection skipping each filtered category, lexicographic-first ordering across multiple IEEE MACs, and the U/L-bit logic in isolation. The value this function returns is what PR #25's `/api/info` redesign will carry in its new `app_instance` field; the two PRs are independent. Stability caveats documented (containers, VMs, multi-NIC, MAC randomization) — fragile in those environments by ansuz acceptance; a stable-id alternative (wallet-derived, persisted) is parked for after ansuz. New parking-lot items: container/Docker handling, multi-NIC tiebreaker semantics, eventual stable-id options.

Ships the data types only: `PeerIdentity` (libp2p ed25519 keypair derived from a wallet via `derive_child("peer/v1")`, with `peer_id()` / `public_key()` / `keypair()` accessors), `ReachabilityRecord` (peer id + multiaddrs + capabilities + last-seen, JSON-serializable wire shape for peer discovery), and `Capability` (namespaced-string newtype with the four canonical `networking:*` constants from the Reid milestone-2 architecture: `MESSAGE_FORWARDING`, `BULK_DATA_CHANNEL`, `TURN`, `SFU`). 11 tests covering determinism of derivation, the public `from_wallet ≡ from_seed(derive_child("peer/v1").seed())` contract, JSON round-trips, and capability namespace extraction. WASM-friendly (`libp2p-identity` + `multiaddr` both compile to WASM); deliberately split from M1's libp2p `Swarm` so Console can derive a peer id from an in-browser wallet without pulling in the transport stack. Built on `auki-identity`, `libp2p-identity` 0.2 (`ed25519` + `peerid` + `serde` features, `default-features = false`), and `multiaddr` 0.18 (with a small local serde adapter — `multiaddr` 0.18 dropped its serde feature). M1 will add the libp2p `Swarm` (TCP/QUIC + Noise + Yamux + Circuit Relay v2) on top of these primitives. Parking-lot items: mDNS coexistence (`_p2p._udp.local.` vs `_auki._tcp.local.`); Wallet→peer-key derivation label evolution; Park-from-home access pattern; off-by-default relay-server plumbing; `ReachabilityRecord` extensibility / versioning.
