### broodsugar's claude · May 5, 09:00 HKT, 2026

`/auki/cluster/1.0.0` participant-exchange protocol landed — ansuz networking-demo deliverable #3, the libp2p half of the **one schema, two transports** promise. New `auki_network::cluster_protocol` module (gated on the `swarm` feature) exposes the protocol id constant `CLUSTER_PROTOCOL = "/auki/cluster/1.0.0"`, a per-request timeout `REQUEST_TIMEOUT = 30s`, the `ClusterRequest` unit struct (serializes as JSON `null` — empty by design, since the protocol's only purpose is fetching the responder's `ParticipantInfo`), the `ClusterResponse = ParticipantInfo` type alias, a `Behaviour = libp2p::request_response::json::Behaviour<ClusterRequest, ClusterResponse>` type alias, and a `behaviour()` constructor that wires both `ProtocolSupport::Full` (every peer can both ask and answer) and the 30s timeout. Codec is libp2p's JSON convenience — same wire bytes the existing `participant::golden_bytes_match_fixture` test pins for `GET /api/info`, so a Park that consumes the HTTP endpoint and a peer that consumes the libp2p response parse identical structs. Wired into the swarm `Behaviour` struct as `cluster: cluster_protocol::Behaviour` — **always-on** (no `Toggle`), the protocol sits idle for swarms that don't participate in a cluster (the dedicated `aukilabs/relay` infrastructure node), so a knob would have been ceremony. The behaviour does **not** auto-respond: receivers handle `request_response::Event::Message::Request{ channel, .. }` themselves and call `behaviour.cluster.send_response(channel, info)` to reply, which is the standard libp2p pattern and lets `auki-py`'s `participant_provider` callable plug in (so `session_now_ns` is fresh on each reply rather than stale at swarm-spawn time). Higher-level orchestration — auto-dialing peers from `cluster.json`, tracking `Joined`/`Left`, holding a peer state map — lives in the next deliverable (cluster runtime / #4); Rust consumers that want fine control (Sentinel) drive the swarm event loop themselves and call `send_request` / `send_response` directly. 3 new tests: `protocol_id_is_locked` (wire-format pin on the protocol id string, same shape as `IDENTIFY_PROTOCOL`'s lock), `request_serializes_as_json_null` (empty unit struct round-trips as JSON `null`), and `two_peers_exchange_participant_info_over_tcp` (full end-to-end: build two swarms, dial, A sends `ClusterRequest`, B receives, B sends back its `ParticipantInfo`, A asserts received == fixture). New libp2p features enabled: `request-response` + `json` (the latter pulls in `serde_json` which we already had on the M0 path). Test counts: 47 unit + 3 integration + 2 doctest with `--features swarm` (was 44 + 3 + 1); no-features and `--features app_instance` paths unchanged at 27 + 3 + 1 / 36 + 3 + 1. No new parking-lot items — multi-cluster participation is single-valued today (daemon's session info is per-session, not per-cluster), and decline-vs-fail isn't load-bearing for ansuz (cluster doc is the trust boundary; libp2p Noise enforces peer-id matching at connection time).

### broodsugar's claude · May 4, 16:30 HKT, 2026

`app_instance::derive()` landed — implementation of ansuz #5, the per-machine identifier that distinguishes two daemons of the same `app` running on different hardware. New `auki_network::app_instance` module behind a default-off `app_instance` feature (non-WASM by design — depends on the `mac_address` crate, which uses platform syscalls `getifaddrs` / `GetAdaptersAddresses`). Recipe locked per ansuz D4: enumerate interfaces, skip loopback (all-zero MAC) and locally-administered MACs (U/L bit `0x02` on the first octet), sort the remaining MACs lexicographically by raw bytes, render the smallest as 12 lowercase hex chars without separators (`aabbccddeeff`). Sorting (rather than relying on OS interface enumeration order) gives a stable selection across platforms and reboots for a fixed hardware set. `DeriveError` enum: `NoNetworkInterfaces` (empty enumeration), `NoSuitableMac` (everything filtered — typical in containers), `Io(std::io::Error)` (syscall failure). Public API: `derive() -> Result<String, DeriveError>` for production; `derive_from(macs: &[[u8; 6]]) -> Result<String, DeriveError>` as the testing seam (pure, no side effects). 9 new tests covering the locked `[0x00,0x16,0x3e,0xab,0xcd,0xef]` → `"00163eabcdef"` cross-language vector, schema (12 lowercase hex), `NoNetworkInterfaces` on empty, `NoSuitableMac` on loopback-only / locally-administered-only, IEEE selection skipping each filtered category, lexicographic-first ordering across multiple IEEE MACs, and the U/L-bit logic in isolation. The value this function returns is what PR #25's `/api/info` redesign will carry in its new `app_instance` field; the two PRs are independent. Stability caveats documented (containers, VMs, multi-NIC, MAC randomization) — fragile in those environments by ansuz acceptance; a stable-id alternative (wallet-derived, persisted) is parked for after ansuz. New parking-lot items: container/Docker handling, multi-NIC tiebreaker semantics, eventual stable-id options.

Lives on the M0 path (no `swarm` feature required) so Park / Console can construct and parse it without pulling in libp2p's transport stack — `libp2p-identity` is already in the default-features set. 8 new tests: round-trip with `Some` and with `None`, snake-case key verification, locked golden-bytes (fixture serializes to exactly the spec'd JSON, with the peer-id derived from a fixed ed25519 seed for reproducibility), explicit-rejection of missing field / wrong type / invalid peer-id string, and a pin on the explicit-`null` vs field-omission distinction. No new dependencies. No parking-lot items raised — the `peer_id` JSON shape (string vs bytes) is settled by both libp2p convention and the spec'd `/api/info` example. ### broodsugar's claude · May 4, 14:30 HKT, 2026

`cluster.json` discovery-doc spec + loader landed (ansuz milestone deliverable #1). New always-on `cluster_doc` module sits alongside the M0 data types — no feature gate, native-only (uses `std::fs`); the rest of the crate's M0 path stays WASM-friendly because Console doesn't import this module. `ClusterDoc` carries `{version: u32, cluster_name: String, peers: Vec<ClusterPeer>}`; each `ClusterPeer` is `{peer_id: libp2p_identity::PeerId (required), addresses: Vec<multiaddr::Multiaddr>, expected_app_id: Option<String>, note: Option<String>}` — `peer_id` required per ansuz D1 (strict, libp2p Noise rejects mismatches at connection time so the doc gives identity continuity across daemon restarts), `expected_app_id` advisory only (authoritative `app_id` rides over the wire from `/api/info`). `LoadError` enum: `Io`, `Parse`, `UnsupportedVersion(u32)`, `InvalidPeerId(String)`, `InvalidMultiaddr(String)` — typed-field errors carry the offending value so an operator can fix the doc from the message alone; manual `Display` + `Error` impls (no `thiserror` dep on the M0 path). `load(&Path) -> Result<ClusterDoc, LoadError>` does a two-phase parse: peeks at `version` first so a future v2 doc with a restructured shape still surfaces `UnsupportedVersion` cleanly instead of an opaque `Parse`. Path layout: `<app_root>/registries/cluster_registries/cluster.json` — flat (single file, not hash-keyed like the existing `sensors/` / `clocks/` / `frames/` siblings); `default_path(app_root)` returns the canonical join, `resolve_path(app_root, cli_override)` honours `cli_override > $AUKI_CLUSTER_DOC > default` (empty env value treated as unset; the override wins over an env var when both are set). 16 new unit tests covering the full schema + every `LoadError` variant + path-resolution precedence + an empty-env-as-unset edge case (env-mutating tests serialize on a process-wide `OnceLock<Mutex>` to keep them parallel-safe alongside the rest of the suite). 3 integration tests in `tests/cluster_doc.rs` exercise the daemon-startup flow end-to-end: `resolve_path` → on-disk JSON → `load` at the default layout, the same with a CLI override, and the operator-typo path returning `InvalidPeerId` with the offending value. New `tempfile` dev-dep. Test counts now 35 unit + 3 integration + 1 doctest with `--features swarm` (was 19 + 0 + 1); 27 unit + 3 integration without features (was 11 + 0 + 0). M0 build with no features still clean. Empty-`addresses` peers are explicitly allowed at parse time (operator may temporarily de-route a pinned peer); consumers that need a dialable address should filter such entries out. `cluster_registries/` is intentionally **flat** for ansuz — lifting the cluster doc into a Cluster Registry primitive (hash-keyed, signed, etc.) is a future evolution, parking-lot item added. The doc is also unsigned for ansuz; cryptographic attestation of the cluster membership list is a future concern. Implements ansuz D1 (strict — peer_id required); D2/D3/D4/D5/D6 unaffected by this PR.

M1a landed — libp2p `Swarm` builder behind the `swarm` feature. Composes `libp2p::tcp` + `libp2p::quic` transports under `libp2p::noise` (authenticated with the peer's ed25519 keypair) and `libp2p::yamux` multiplexing, with a minimal `identify` + `ping` `NetworkBehaviour`. Identify protocol id is `/auki/identify/1.0.0` (stable wire format); `agent_version` is the per-deployment knob. Idle connections close after 60s (ping resets the timer). 4 new tests + 1 doctest covering `build_swarm` correctness, mutual `identify::Event::Received` round-trip over TCP, the same over QUIC, and listening on multiple addresses simultaneously. `swarm` is **default-off** so the M0 path stays WASM-compilable for Console (which uses `default-features = false`); enabling the feature pulls in `libp2p` 0.56 (features: `tokio`, `tcp`, `quic`, `noise`, `yamux`, `identify`, `ping`, `macros`, `ed25519`) and `thiserror`. Workspace test count: 11 → 15 unit + 1 doctest. ### broodsugar's claude · May 2, 16:10 HKT, 2026

Crate created — Layer 1 of the Reid milestone-2 networking stack. Ships the data types only: `PeerIdentity` (libp2p ed25519 keypair derived from a wallet via `derive_child("peer/v1")`, with `peer_id()` / `public_key()` / `keypair()` accessors), `ReachabilityRecord` (peer id + multiaddrs + capabilities + last-seen, JSON-serializable wire shape for peer discovery), and `Capability` (namespaced-string newtype with the four canonical `networking:*` constants from the Reid milestone-2 architecture: `MESSAGE_FORWARDING`, `BULK_DATA_CHANNEL`, `TURN`, `SFU`). 11 tests covering determinism of derivation, the public `from_wallet ≡ from_seed(derive_child("peer/v1").seed())` contract, JSON round-trips, and capability namespace extraction. WASM-friendly (`libp2p-identity` + `multiaddr` both compile to WASM); deliberately split from M1's libp2p `Swarm` so Console can derive a peer id from an in-browser wallet without pulling in the transport stack. Built on `auki-identity`, `libp2p-identity` 0.2 (`ed25519` + `peerid` + `serde` features, `default-features = false`), and `multiaddr` 0.18 (with a small local serde adapter — `multiaddr` 0.18 dropped its serde feature). M1 will add the libp2p `Swarm` (TCP/QUIC + Noise + Yamux + Circuit Relay v2) on top of these primitives. Parking-lot items: mDNS coexistence (`_p2p._udp.local.` vs `_auki._tcp.local.`); Wallet→peer-key derivation label evolution; Park-from-home access pattern; off-by-default relay-server plumbing; `ReachabilityRecord` extensibility / versioning.
