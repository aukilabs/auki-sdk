# Auki SDK vision

The Auki SDK should make the physical world as easy to build on as the web.
Phones, robots, sensors, and services should be able to share what they know
about a place, understand one another's observations, and work together.

This is the idea behind Auki's **real world web**: information about physical
places that people and apps can discover and use, with permission from those
who share it.

## A shared understanding of a place

A robot entering a warehouse should be able to use a map that already exists.
A camera should be able to share an observation that another device can locate
and understand. A developer should be able to build on those contributions
without recreating an entire picture of the place.

Each place can have its own **Domain**, with owners deciding what to share and
who may use it. Like websites, these places can be independently operated while
participating in a common network.

## Five questions

The real world web is built around five questions that participants should be
able to answer:

1. **Identity** — Who produced this information?
2. **Space** — Where did this happen?
3. **Time** — When did this happen?
4. **Connection** — How do I reach you and exchange information?
5. **Compensation** — How do I compensate you for useful data or work?

These questions let knowledge from one device become useful to another.
Compensation gives people a reason to contribute data, computing power, and
services, helping the network grow through useful participation.

## The SDK's role

The SDK should make it easy for developers to bring their apps into this
network, using the devices and languages they already work with. Developers
should be able to choose what their apps share and build services that others
can use.

Connecting apps and exchanging data is the foundation. Shared spatial
understanding and compensation are part of the wider ambition. The
[networking reference](../reference/networking.md) describes what the SDK
supports today.
