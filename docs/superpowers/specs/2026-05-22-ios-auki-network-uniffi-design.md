# iOS Auki Network UniFFI Test App Design

## Goal

Build the first iOS test app that consumes generated Swift bindings from the Rust SDK crates. The app proves that an iOS host can use the generated UniFFI packages for behaviorful crates plus generated SwiftProtobuf data types, then exchange protobuf `MessageEnvelope` payloads with a browser peer over the Rust `auki-network` implementation.

The target proof is:

```text
browser JavaScript client
  -> js-libp2p transport using auki-network wasm helpers
  -> /auki/message/0.0.1
  -> Rust auki-network compiled into the generated Swift binding package
  -> iOS test app
```

## Hard Constraints

Swift must not use swift-libp2p. The point of the native binding layer is to reuse the same Rust networking crate across Swift, Python, and other native hosts.

The iOS test app is a consumer of generated bindings. It should not hand-write SDK networking behavior in Swift.

Swift owns test-app UI, test orchestration, and protobuf data conversion. Rust owns libp2p, transports, protocol handlers, runtime lifecycle, peer identity derivation, and wire framing.

Generated Swift protobuf bindings are data-only artifacts. They are produced locally under `bindings/swift/auki-proto/` and are not committed.

## Current Repo State

`auki-identity` already has Swift UniFFI generation enabled and can provide wallet and seed material to native clients.

`auki-network` has a native UniFFI adapter, but its current exported surface is intentionally small: peer identity derivation, the peer derivation label, public-key protobuf bytes, and networking capability constants.

`auki-network` Swift binding generation is currently disabled. The full runtime is also behind the `swarm` feature, so simply enabling `[bindings.swift]` is not enough for a useful iOS client.

The browser path is already the right shape: the generated JavaScript package uses Rust wasm helpers for canonical identity/protocol values and js-libp2p for browser transport.

## Architecture

The architecture has three layers.

Rust SDK crates are the source of behavior:

- `auki-identity` exports wallet and seed primitives through UniFFI.
- `auki-network` exports the native message-networking facade through UniFFI.
- `auki-proto` owns protobuf schemas and generated Rust types.

Generated Swift packages are the SDK surface consumed by iOS:

- `bindings/swift/auki-identity/` provides the Swift package generated from `auki-identity`.
- `bindings/swift/auki-network/` should be generated from `auki-network` once its Swift binding is enabled.
- `bindings/swift/auki-proto/` is generated locally from root `.proto` schemas and stays ignored by git.

The iOS test app imports those generated packages and contains only host-app code:

- seed loading or test seed selection;
- node start/stop controls;
- listen-address display;
- browser peer/address input;
- send-message trigger;
- received-message log.

The high-level message facade belongs in Rust `auki-network` and is exported by UniFFI. The generated Swift binding exposes that facade to the test app. The test app must not create a parallel Swift networking abstraction.

Swift sees strings and bytes from the generated binding:

- peer ids as strings;
- multiaddrs as strings;
- protobuf messages as encoded `Data`;
- errors as typed UniFFI errors;
- event records as simple Swift structs generated by UniFFI.

Swift does not see `libp2p::Swarm`, `PeerId`, `Multiaddr`, Tokio channels, Rust streams, or generic protocol types.

## Component Boundaries

`auki-proto`:

- owns `MessageEnvelope` and `MessageAck` schemas;
- generates SwiftProtobuf types for iOS data conversion;
- remains separate from UniFFI.

`auki-network`:

- exposes a native Swift binding generated by UniFFI;
- owns `/auki/message/0.0.1`;
- owns the Rust runtime and libp2p transport;
- accepts encoded protobuf bytes from Swift and validates and frames them internally;
- emits encoded protobuf bytes back to Swift.

`auki-identity`:

- continues to expose wallet and seed primitives;
- remains the source for persistent identity material.

`auki-domain`:

- stays out of the first milestone;
- becomes the next native binding layer once raw message interop is proven.

`iOS test app`:

- lives outside the Rust crate internals;
- depends on generated Swift packages;
- proves the generated packages are usable from a real iOS host;
- contains no SDK protocol implementation beyond test orchestration.

## Data Flow

Outbound test-app message:

1. Swift constructs `Auki_Message_MessageEnvelope` using generated SwiftProtobuf.
2. Swift serializes it to `Data`.
3. The test app calls the generated `auki-network` Swift binding.
4. Rust `auki-network` decodes or validates the bytes as `auki_proto::message::MessageEnvelope`.
5. Rust opens `/auki/message/0.0.1` through `auki-network` and writes the length-prefixed protobuf envelope.
6. The browser receives the envelope through js-libp2p and decodes it with generated JavaScript/TypeScript protobuf bindings.

Inbound test-app message:

1. Rust `auki-network` receives `/auki/message/0.0.1`.
2. Rust parses the length-prefixed protobuf envelope.
3. Rust queues a UniFFI-safe event containing sender peer id and encoded envelope bytes.
4. The test app polls or awaits the next event through the generated Swift binding.
5. Swift decodes the bytes with SwiftProtobuf.

## Test App Swift Shape

The first iOS test app should import generated packages. The exact generated names can shift with UniFFI, but the dependency direction is fixed:

```swift
import auki_identity
import auki_network
import AukiProto

let wallet = try Wallet.fromSeed(seed: seed)
let node = try AukiMessageNode.fromWalletSeed(
    seed: try wallet.seed(),
    listenAddrs: ["/ip4/0.0.0.0/udp/0/webrtc-direct"],
    agentVersion: "auki-ios-test-app/0.1"
)

try await node.start()
let localPeerId = node.peerId()
let listenAddrs = node.listenAddrs()

var envelope = Auki_Message_MessageEnvelope()
envelope.kind = "test.ping"
envelope.body = Data("hello".utf8)

try await node.dial(peerId: browserPeerId, addrs: browserAddrs)
try await node.sendMessageEnvelopeBytes(peerId: browserPeerId, bytes: envelope.serializedData())

let event = try await node.nextEvent()
```

The exact UniFFI async shape can change during implementation if UniFFI constraints require a blocking poll, callback sink, or handle-based API. The design requirement is that the test app consumes generated Swift APIs and does not bypass them.

## Error Handling

Use typed UniFFI errors for:

- invalid seed length;
- invalid peer id;
- invalid multiaddr;
- runtime already started or already stopped;
- listen failure;
- dial failure;
- protobuf decode failure;
- send timeout;
- remote protocol failure;
- receive queue closed.

Errors should include enough string context for iOS logs, but Swift should not parse error strings for control flow.

## Binding Generation Changes

`crates/auki-network/bindings.toml` should enable Swift once the exported Rust facade is useful.

The binding generator needs a way to build the native library with runtime features for Swift/XCFramework output. The current generator builds the library with default features; `AukiMessageNode` requires `swarm` plus the browser-compatible WebRTC Direct dependency path that is currently gated by `browser_probe`.

The generator should keep feature selection crate-owned through `bindings.toml`, rather than hardcoding `auki-network` in the shared Python script.

## First Milestone

The first milestone is not full cluster membership. It is:

- generated Swift protobuf package builds locally;
- `auki-network` Swift XCFramework builds with the message-node facade;
- an iOS test app imports generated `auki-identity`, `auki-network`, and `AukiProto` packages;
- the test app can create a node from wallet seed;
- the node can listen and report dialable addresses;
- a browser client can dial the iOS node;
- browser and iOS exchange one `MessageEnvelope`;
- both sides verify locked identity and protobuf wire vectors.

## Non-Goals

Do not introduce swift-libp2p.

Do not expose raw libp2p or Tokio types to Swift.

Do not implement SDK networking behavior directly in the iOS test app.

Do not route protobuf schema generation through UniFFI.

Do not bind `auki-domain` in the first milestone.

Do not implement full `convert_time`, `convert_pose`, resource catalogs, typed sensor streams, Manager election, or Discovery-backed cluster lifecycle in this slice.

Do not commit generated Swift protobuf output.

## Test Plan

Add Rust tests for the message-node internals before exposing them over UniFFI.

Keep locked vectors for:

- wallet seed to peer id;
- private-key protobuf bytes where browser import depends on them;
- `MessageEnvelope` protobuf bytes;
- `/auki/message/0.0.1` length-prefixed framing.

Add Swift binding smoke tests that instantiate the generated package, derive a peer id, and exercise message-node construction without requiring network access.

Add an iOS test-app smoke path that imports the generated packages and starts the message node.

Add an interop smoke that runs a browser js-libp2p client against the iOS test app's native message node and exchanges one message envelope.

## Implementation Order

1. Extend `auki-network` with a Rust message-node facade over the existing runtime/protocol pieces.
2. Add focused tests for facade lifecycle, address parsing, message framing, and shutdown.
3. Expose the facade through UniFFI with Swift-safe records, errors, and byte buffers.
4. Update binding generation so `auki-network` Swift/XCFramework builds with the required native features.
5. Generate the Swift package and verify the XCFramework.
6. Build the iOS test app against generated Swift packages.
7. Add browser-to-iOS-test-app interop smoke for `/auki/message/0.0.1`.
8. Only after message interop passes, plan the `auki-domain` Swift binding layer.
