# SDK Signaled WebRTC Transport Design

## Goal

Build an SDK-owned, bidirectional Discovery-signaled WebRTC data-channel transport so browser peers and native Swift/iOS peers can join the same Auki Domain, discover each other, and exchange the standard Domain protocols without app-specific signaling code.

The first product proof is:

```text
iOS peer
  -> uses generated SDK Swift bindings
  -> advertises /auki-webrtc-signaling/.../p2p/<peer-id>
  -> joins or creates a Domain through Discovery
  -> publishes camera catalogs and streams camera frames

Overwatch browser peer
  -> uses generated SDK JavaScript/WASM bindings
  -> advertises /auki-webrtc-signaling/.../p2p/<peer-id>
  -> joins or creates the same Domain through Discovery
  -> fetches iOS catalogs and opens the camera stream

Either peer
  -> can initiate signaled WebRTC connections to the other
  -> can request info, catalogs, registry entries, joins, and streams
```

## Current Repo Context

The browser SDK path already has the right shape. `bindings/javascript/auki-network/index.js` exposes `AukiNetworkPeer.configureDiscoverySignaling(...)`, advertises `/auki-webrtc-signaling/<discovery-url>/p2p/<peer-id>`, polls Discovery's `/signals` mailbox, and routes framed protocols plus `/auki/stream/0.1.0` over WebRTC data channels.

The native Rust path is different today. `DomainClusterManager` is built around `NetworkRuntime`, which owns a libp2p swarm and listens on TCP/QUIC/WebRTC Direct addresses depending on features. That path is correct for native-to-native daemons, but it is not the right browser interop default because browsers need an offer/answer/ICE exchange through Discovery.

The native Discovery client currently focuses on the cluster and node directory. The `/signals/{peer_id}` mailbox is exposed to wasm JavaScript, not to native UniFFI bindings. The iOS camera streamer currently tries to listen on `/ip4/0.0.0.0/udp/0/webrtc-direct`; that can be retained as a probe path, but the production browser/native route should be Discovery-signaled WebRTC.

## Design Constraints

The SDK owns signaling, address format, protocol framing, data-channel routing, Domain join, catalogs, registries, and stream semantics. Application code should only pass configuration, publish sensors/resources, accept stream requests, and push stream entries.

Native Swift code inside an example app must not implement Discovery signaling, WebRTC offer/answer routing, request framing, stream framing, or Domain membership. Swift support code generated by the SDK package may integrate with platform WebRTC APIs because browser and iOS expose different WebRTC implementations.

The transport must be bidirectional. Any peer that advertises a signaled address can dial any other signaled peer and can also accept incoming signaled dials.

The new surface should not replace the existing libp2p `DomainClusterManager` daemon path. It adds a signaled peer path for browser/native interop where WebRTC signaling is required.

No app backend is introduced. Discovery remains the rendezvous and signaling mailbox.

## Recommended Architecture

Use a shared SDK state machine with platform WebRTC backends.

```text
auki-network
  signaled_address
  discovery_signals
  signaled_peer_core
  framed protocol router
  stream channel router
  UniFFI records/errors for native bindings
  wasm/JavaScript exports for browser bindings

generated JavaScript auki-network package
  browser RTCPeerConnection backend
  thin adapter around signaled peer core semantics

generated Swift auki-network package
  Apple WebRTC backend
  thin adapter around signaled peer core semantics

auki-domain
  signaled Domain peer facade over a signaled network peer
  generated native and browser bindings expose the same high-level Domain operations
```

Rust owns the transport-neutral state machine: connection ids, address parsing, signal message validation, handler registration, protocol selection, request timeouts, stream ids, and lifecycle state. Platform bindings own the raw `RTCPeerConnection` and `RTCDataChannel` calls.

The first Apple backend lives in the generated Swift SDK package, not in `examples/ios`. Its dependency shape is SwiftPM with an XCFramework-backed WebRTC package so Xcode projects can consume generated SDK packages without CocoaPods. The backend boundary keeps that dependency replaceable: if the project later vendors its own `WebRTC.xcframework`, the SDK API and Rust core remain unchanged.

## `auki-network` Modules

### `signaled_address`

Owns the canonical address contract:

```text
/auki-webrtc-signaling/<base64url-trimmed-discovery-url>/p2p/<peer-id>
```

Responsibilities:

- format a signaled address from `(discovery_url, peer_id)`;
- parse a signaled address into `(discovery_url, peer_id)`;
- reject malformed base64, empty Discovery URLs, and invalid peer ids;
- normalize Discovery URLs by trimming trailing slashes before encoding.

The same format is used by browser, Swift, future Python bindings, and Discovery cluster entries.

### `discovery_signals`

Extends native `DiscoveryClient` and generated bindings with the mailbox already used by the browser package:

```text
POST /signals/{recipient_peer_id}
GET  /signals/{recipient_peer_id}?since={id}&timeout_ms={ms}
```

Binding records:

```text
SignalRequest {
  recipient_peer_id: string
  from_peer_id: string
  connection_id: string
  kind: "offer" | "answer" | "candidate" | "close"
  payload_json: string
}

SignalMessage {
  id: u64
  recipient_peer_id: string
  from_peer_id: string
  connection_id: string
  kind: string
  payload_json: string
  created_ns: i64
}

SignalPollQuery {
  peer_id: string
  since: u64
  timeout_ms: u64
}
```

The Rust client keeps typed JSON values internally where useful. Bindings use strings for payload JSON because SDP and ICE payloads are platform-shaped.

### `signaled_peer_core`

Owns the transport-neutral peer lifecycle.

State per local peer:

- local peer id;
- Discovery URL;
- local signaled multiaddr;
- signal cursor;
- registered framed handlers by protocol;
- registered stream handlers by protocol;
- connection states by connection id;
- connection states by remote peer id;
- timeout and polling policy.

State per remote connection:

- remote peer id;
- connection id;
- role: initiator or responder;
- status: pending offer, pending answer, connecting, connected, closing, closed, failed;
- pending ICE candidates queued before remote description is installed;
- pending outbound protocol channels waiting for data-channel open.

Core emits platform commands instead of directly calling WebRTC:

```text
CreatePeerConnection(connection_id, remote_peer_id, role)
CreateDataChannel(connection_id, label)
SetLocalDescription(connection_id, description_json)
SetRemoteDescription(connection_id, description_json)
AddIceCandidate(connection_id, candidate_json)
CloseConnection(connection_id)
```

Platform backends feed events back:

```text
LocalDescriptionReady(connection_id, description_json)
IceCandidateReady(connection_id, candidate_json)
ConnectionStateChanged(connection_id, state)
DataChannelOpened(connection_id, label, channel_id)
DataChannelMessage(channel_id, bytes)
DataChannelClosed(channel_id)
```

This keeps the state machine testable in Rust without a real WebRTC stack.

### Framed Protocol Router

The router supports request/response protocols over data channels:

```text
/auki/join/0.0.1
/auki/info/0.0.1
/auki/sensors/0.0.1
/auki/resources/0.0.1
/auki/registries/0.0.1
/auki/diagnostic/0.0.1
```

Each request opens or reuses a data channel labelled with the protocol. Payloads use the same length-prefixed byte framing as the existing JavaScript adapter. The handler registry receives `(remote_peer_id, protocol, bytes)` and returns response bytes or a typed error.

### Stream Channel Router

The stream router supports `/auki/stream/0.1.0` over WebRTC data channels.

The wire messages stay aligned with the existing browser adapter:

```text
{ "request": { "sensor_id": "..." } }
{ "accept": { "sensor_id": "...", "sensor_hash": "...", "clock_id": "...", "clock_hash": "...", "frame_id": "...", "frame_hash": "..." } }
{ "entry": { "timestamp_ns": 123, "seq": 0, "payload": [1, 2, 3] } }
{ "decline": { "kind": "sensor_not_found", "detail": "..." } }
{ "end_of_stream": { "kind": "source_ended", "detail": "..." } }
```

The SDK core owns stream ids, open requests, accept/decline decisions, sequence ordering, finish semantics, and errors. Platform data channels are only byte pipes.

## `auki-domain` Signaled Peer Facade

Add a Domain facade that composes a signaled network peer instead of a libp2p swarm.

High-level native and browser binding shape:

```text
AukiSignaledDomainPeer.start(config)
AukiSignaledDomainPeer.localPeerId()
AukiSignaledDomainPeer.multiaddrs()
AukiSignaledDomainPeer.createOrJoin(discovery_url, cluster_name, target_mode)
AukiSignaledDomainPeer.shutdown()

AukiSignaledDomainPeer.setStaticSensorCatalogJson(json)
AukiSignaledDomainPeer.setStaticResourceCatalogJson(json)
AukiSignaledDomainPeer.setStaticRegistryEntriesJson(json)

AukiSignaledDomainPeer.drainStreamOpenRequests(max_events)
AukiSignaledDomainPeer.acceptStreamOpen(responder_id, manifest_json)
AukiSignaledDomainPeer.declineStreamOpen(responder_id, reason)
AukiSignaledDomainPeer.pushStreamEntry(stream_id, entry)
AukiSignaledDomainPeer.finishStream(stream_id)

AukiSignaledDomainPeer.fetchParticipantInfo(peer_id)
AukiSignaledDomainPeer.fetchSensorCatalog(peer_id)
AukiSignaledDomainPeer.fetchResourceCatalog(peer_id)
AukiSignaledDomainPeer.fetchRegistryEntry(peer_id, request_json)
AukiSignaledDomainPeer.openStreamBytes(peer_id, request_json, payload_kind)
```

This facade should share as much Domain membership/catalog/stream logic as possible with `DomainClusterManager`, but it must not require a libp2p `NetworkRuntime`. If a reusable core extraction is needed, the extraction should split Domain behavior from libp2p transport rather than duplicating membership behavior.

## Domain Join Behavior

Create/join mirrors the browser peer flow and becomes the shared SDK behavior:

1. Start the signaled network peer.
2. Configure Discovery signaling and begin polling `/signals/<local_peer_id>`.
3. Register handlers for join, info, sensors, resources, registries, and stream protocols.
4. Advertise the signaled multiaddr in Discovery.
5. Try create for `Create` or `JoinOrCreate`.
6. If created, initialize local membership as Manager and start Discovery liveness.
7. If already exists or target is `Join`, list Discovery, find the Manager address, and send `/auki/join/0.0.1` over the signaled transport.
8. Apply the join accept response and refresh remote catalogs.

When a signaled peer is Manager, it must answer join requests from both browser and native peers. When it is a member, it must answer info/catalog/registry/stream requests from any admitted peer.

## Native Swift Binding Behavior

The generated Swift SDK package exposes the signaled network/domain classes. App code should not import a low-level WebRTC package directly for SDK transport.

Swift package responsibilities:

- construct the Apple WebRTC peer connection factory;
- create data channels requested by the SDK state machine;
- serialize local SDP and ICE candidates into JSON payloads;
- apply remote SDP and ICE candidates from SDK events;
- deliver data-channel bytes into the SDK router;
- expose async Swift methods generated from UniFFI for the public SDK facade.

The generated Swift package exposes a narrow backend configuration record:

```text
NativeWebRtcConfig {
  ice_servers_json: string
  data_channel_ordered: bool
  connect_timeout_ms: u64
}
```

The default v1 ICE config is an empty ICE server list. Same-LAN tests should work with host candidates. TURN/STUN configuration is passed as JSON so apps can supply production ICE servers later without changing the binding API.

## Browser Binding Behavior

The JavaScript package keeps the current browser `RTCPeerConnection` implementation but moves address parsing, signal DTO validation, and protocol routing toward the shared SDK contract.

Compatibility requirements:

- existing `AukiNetworkPeer.configureDiscoverySignaling(...)` keeps working;
- existing Overwatch `AukiBrowserDomainPeer.createOrJoin(...)` keeps working during migration;
- new `AukiSignaledDomainPeer` browser surface uses the same public shape as native bindings where JavaScript conventions allow.

## Error Handling

Discovery failures are surfaced as typed transport/status errors with the URL and endpoint class.

Malformed signal messages are ignored after recording a diagnostic event. A malformed signal from one peer must not stop the polling loop.

Offer/answer conflicts are resolved by connection id. If both peers dial simultaneously, each connection id is independent; the first connected state for a remote peer becomes the preferred connection, and the duplicate is closed cleanly.

Connection timeout closes the pending peer connection and fails waiting framed/stream requests with a timeout error.

Data-channel close while a request is pending fails that request. Data-channel close while a stream is active emits `connection_lost` to the consumer and removes producer fanout state.

Discovery liveness is best-effort. A failed liveness tick records diagnostics and retries on the next interval.

## Testing Strategy

Rust unit tests cover the transport-neutral pieces:

- signaled address format/parse/normalize/reject;
- Discovery signal request/poll JSON mapping;
- signal state machine for offer, answer, candidates, close, and malformed messages;
- simultaneous dial conflict resolution;
- framed protocol request/response routing with fake platform channels;
- stream request, accept, entry, decline, and finish routing with fake platform channels.

Generated JavaScript tests cover:

- existing browser signaling behavior remains compatible;
- the new shared address helpers produce the same multiaddr strings;
- browser-to-browser signaled framed requests still pass;
- browser-to-browser stream open still passes.

Generated Swift tests cover:

- Swift package imports the signaled network/domain surfaces;
- fake WebRTC backend can drive the state machine without camera hardware;
- signal DTOs round-trip through UniFFI;
- Domain peer facade can publish catalogs and accept a fake stream open.

Integration smoke tests cover:

- two browser peers in Overwatch joining and streaming as today;
- native Swift fake backend to browser fake backend at the SDK layer;
- physical iOS device to Overwatch browser with real WebRTC data channels and camera frames.

The physical-device test is the only required manual test because iOS camera permission and Apple WebRTC behavior are not fully covered by simulator or host Rust tests.

## Migration Plan

The iOS camera streamer should switch from `DomainClusterManager` WebRTC Direct listen addresses to `AukiSignaledDomainPeer` once the SDK facade exists. The app keeps camera capture, logging, catalog JSON, and stream fanout, but all signaling and protocol transport moves behind SDK bindings.

Overwatch should migrate from `AukiBrowserDomainPeer` to the shared signaled Domain facade after the browser package exposes it. Until that migration is complete, Overwatch can keep its existing browser peer because it already follows the target signaling contract.

The old WebRTC Direct browser probe remains useful as a lower-level transport proof and diagnostic tool. It should not be the primary iOS-to-browser Domain path.

## V1 Boundaries

V1 supports Discovery-signaled WebRTC data channels and app-supplied ICE configuration. It does not ship relay reservation, DCUtR, TURN credential provisioning, end-to-end signal encryption, or signed Discovery signal authentication.

Those capabilities belong in later SDK transport hardening. The v1 architecture keeps room for them by centralizing signaling and connection state in `auki-network`.
